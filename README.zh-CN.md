# renmori

**面向商业 Ren'Py 游戏的全量数据保护工具。**

renmori 是一个「构建期工具 + 原生运行时」，输入一个已经 build 好的 Ren'Py 8.x
游戏，输出受保护的发行版本。游戏里的所有数据——脚本、立绘、CG、音频、视频、
**字体**、翻译、配置——都会被打进加密容器，只在运行中的引擎内部解密。目标是让
常见的解包/反编译工具（以及只会调用它们的 agent）直接失败，并让每次构建都不同，
使得没有任何一个通用解包器能跨游戏生效。

> **状态：** 早期开发中。设计见 [docs/architecture.md](docs/architecture.md)，
> 当前进度见下方 [路线图](#路线图)。

## 它能挡住什么——以及挡不住什么

先读这一段。**在玩家机器上运行的游戏，永远做不到不可破解。** 引擎要跑就必须能读
自己的资源，所以密钥和解密逻辑一定随游戏一起发出，屏幕也永远可以被截取。所有本地
DRM 最终都被破过。renmori 不会假装例外。

renmori 真正带来的是：

1. **现成工具直接失效。** `unrpa`、`rpatool`、`RenPack`、`RenpyEx`、`unrpyc`
   （含 `--try-harder` 和 `un.rpyc` 注入）在受保护版本上都跑不通。绝大多数「扒资源」
   「泄脚本」事件其实就是有人跑了这些工具，这一招即可挡掉。
2. **破解不可移植。** 每次构建的容器布局、脚本编码、密钥推导都不一样。逆向一个游戏
   只能得到针对*那一个游戏、那一个版本*的工具，而不是通用解包器。你买的不是
   「不可破」，而是「不能批量破」。
3. **磁盘上任何时候都没有明文**——字体也不例外。

如果你的需求是「让高水平、下定决心的攻击者永远提不出哪怕一个资源」，那么没有任何
客户端工具（renmori 或别的）能做到。renmori 把提取成本抬到「专门针对单个游戏、单个
版本的专家级投入」，这足以让绝大多数游戏不值得被破。

## 设计优先级（按顺序）

1. **性能第一。** 任何与运行性能冲突的保护手段都会被砍掉。默认不用重型加壳/虚拟化
   保护；加密走硬件加速（AES-NI）且为原生实现；完整性校验只在启动时做一次，绝不进
   热路径。受保护版本在帧时间、切场景、CG/视频播放上必须与未保护版本无可感知差异。
2. **对开发者友好 / 可进 CI。** 对标准 Ren'Py 构建产物跑一条命令即可，退出码明确，
   配置走文件或环境变量，附带 GitHub Actions 示例。不要求改动游戏源码。
3. **保护强度。** 主要靠每次构建的多态化实现（零运行时开销），而非运行时死守。

## 工作原理（四层）

| 层 | 做什么 |
|----|--------|
| **资源层** | `game/` 下所有文件打进自定义加密容器（不再用 RPA）。原生模块接管 `renpy.loader`，返回解密后的流式文件对象。大文件（视频/音频）按偏移分块解密，绝不整包解进内存。 |
| **脚本层** | 编译脚本改用自定义 AST 格式而非标准 `.rpyc`，类名/字段每次构建都重映射，基于 pickle 的反编译器无从还原。内嵌 Python 在构建期编译并加密。 |
| **引擎层** | 引擎与标准库打包并在启动时做完整性校验。只加载构建期签名过的脚本；丢进游戏目录的外来 `.rpy`/`.rpyc` 一律拒绝（挡住注入式反编译）。发行版关闭开发者控制台和导出类命令。 |
| **启动器** | 各平台一个原生启动器替换 Ren'Py 自带的，从加密容器引导内嵌 Python，运行时推导密钥，磁盘上不存明文 key。 |

详细设计见 [docs/architecture.md](docs/architecture.md)，诚实的威胁模型见
[docs/threat-model.md](docs/threat-model.md)。

## 用法（计划中的 CLI）

```bash
renmori protect ./dist/MyGame-1.0-pc -o ./dist/MyGame-1.0-pc-protected
```

默认零配置。可选的 `renmori.toml` 控制目标平台、排除清单和强度等级。命令会输出一份
构建清单（哪些文件被保护、容器格式版本、构建指纹），方便在 CI 里做断言。

## 平台

Windows、macOS、Linux / Steam Deck。

- **Steam：** 显式放行 Steam overlay 的进程注入；反篡改保持最小，绝不挡 overlay。
  **不要**再给构建套 Steam 自带 DRM。成就与云存档走 Ren'Py 原生 API，不受影响。
- **macOS：** **不强制公证。** renmori 只解密*数据*、绝不执行解密出的代码，因此不需要
  硬化运行时特殊 entitlement，也不会逼你去付费签名。Apple Silicon 要求二进制至少有
  ad-hoc 签名才能运行（免费、无需账号）——构建工具会自动完成。若你有 Developer ID，
  二进制保持可重新签名与可公证。

## Open-core（开放内核）模式

renmori 采用 **open-core**：框架免费开源，真正决定「能否被通杀」的那部分闭源。

- **开源**（本仓库）：CLI、`renpy.loader` hook 框架 / 运行时 SDK、基线容器格式 v1
  规范、标准加密原语调用、CI 集成、文档、样例、测试。单独可用，提供基线强度。
- **闭源**（以预编译二进制插件形式交付，由开源 CLI 调用）：多态引擎、密钥推导逻辑、
  反篡改运行时。它们是阻止「通用解包器」出现的关键，而多态引擎永不下发给玩家——所以
  闭源在这里才真正有意义。

开源 CLI 与闭源二进制通过一个稳定、文档化的进程接口通信。接口开源，实现闭源。
