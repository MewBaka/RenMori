# 插件接口

English version: [interface.md](interface.md)

RenMori 采用开核架构。开放的 `renmori` 命令行工具是集成点：它解析配置，准备输出与备份，驱动面向用户的流程，并始终提供基线容器格式。强保护——逐构建多态引擎、运行时密钥派生，以及原生核心与启动器——位于一个封闭插件之中，以预构建组件的形式分发，绝不以源码形式分发。

本文档定义二者之间稳定的进程契约。该契约公开，使开放工具与封闭插件得以各自独立地版本化与发布；仅插件的实现是封闭的。

## 发现

开放工具按如下顺序定位插件：

- `renmori protect` 的 `--plugin <path>` 参数
- `RENMORI_PLUGIN` 环境变量
- 未找到插件——工具运行基线格式，并拒绝任何非基线的 `strength`

`<path>` 是一个可执行文件，或一个由开放工具以当前 Python 解释器运行的 `.py` 脚本。插件只有在一次成功的 `capabilities` 握手（见下）之后才被使用；握手失败的插件被视作不存在，转而走基线路径。

## 传输

每次调用都是一个短生命周期的子进程。第一个参数选择操作。请求（当需要时）是 **stdin** 上的单个 JSON 对象；响应是 **stdout** 上的单个 JSON 对象。所有人类可读的日志均写入 **stderr**，以保证 stdout 可被机器解析。退出码在成功时为 0，失败时非零。所有字段名与枚举值均为 ASCII 且与区域设置无关。

两个对象都携带一个 `interface` 整数。开放工具发送其支持的最高版本，并拒绝其 `capabilities` 未包含该版本的插件。

## 操作

### `capabilities`

无请求体。插件打印一个描述自身的 JSON 对象并以 0 退出：

| 字段 | 含义 |
|-------|------|
| `interface` | 插件支持的最高接口版本 |
| `name` | 插件显示名 |
| `version` | 插件发布版本 |
| `strengths` | 插件接受的 `strength` 取值，由强到弱 |
| `platforms` | 插件能产出的目标平台键 |

### `protect`

stdin 上的请求对象：

| 字段 | 含义 |
|-------|------|
| `interface` | 由开放工具选定的接口版本 |
| `source_dir` | 待读取的构建发行版；插件不得修改它 |
| `output_dir` | 受保护构建的写入位置；由插件创建，且必须尚不存在 |
| `strength` | 插件已通告的某个 `strengths` 取值 |
| `platforms` | 一份显式的目标平台键列表，或 `null` 表示从 `source_dir/lib/py3-*` 自动探测 |
| `launcher` | 是否将密钥绑定到一个原生启动器并一同下发 |
| `exclude` | 留在容器之外的、相对游戏目录的 glob |
| `chunk_size` | 容器分块大小（字节），或 `null` 表示插件默认值 |
| `lockdown` | 是否在构建中禁用开发者控制台、开发者模式与导出数据的子命令 |
| `keys` | 一个对象；预留给密钥材料或密钥来源指令，默认为空 |

插件将 `source_dir` 复制到 `output_dir`，把每一项数据与脚本封入多态容器，为每个目标平台下发其原生核心（以及启动器，当被请求时），写出运行时扩展，移除它所封装的明文原件，并在 stdout 上打印响应对象：

| 字段 | 含义 |
|-------|------|
| `interface` | 本次响应的接口版本 |
| `status` | `"ok"` |
| `strength` | 实际应用的强度 |
| `platforms` | 已产出的目标平台键 |
| `container` | `game/` 下的容器文件名 |
| `container_sha256` | 容器的十六进制 SHA-256 |
| `files` | 已封装的条目数 |
| `scripts` | 已变换的脚本数 |
| `cores` | 每个已下发的原生核心一条 `{platform, filename}` |
| `launcher` | 分平台的启动器文件名，或 `null` |

失败时插件打印 `{"interface": N, "status": "error", "message": "<reason>"}` 并以非零退出。开放工具转述该消息，以其运行失败码退出，并在力所能及的范围内不留下残缺的 `output_dir`。

## 职责划分

- 开放工具负责：参数与 `renmori.toml` 解析、输出/备份决策及其所涉的任何复制或移动、预检摘要与确认、它依据响应写出的清单，以及所有本地化输出
- 插件负责：容器格式及其逐构建随机化、密钥派生、原生核心与启动器，以及 `output_dir` 之下确切的磁盘结果

原地保护对插件而言表达为一对普通的 `source_dir` → `output_dir`：开放工具先将原件移到一旁（移至备份，或移至事后丢弃的临时目录），并将原路径命名为 `output_dir`，因此插件从不需要一个原地模式。

## 版本与完整性

`interface` 仅在请求或响应结构发生破坏性变更时递增。一个插件可同时支持多个版本；开放工具选取二者共有的最高版本。追加的、可选的字段不触发版本递增。

由插件产出的构建，意在能够与第三方用开放框架加一个手写弱引擎拼装出的构建相区分：清单中可携带一个由运行时校验的构建指纹。该绑定与封闭组件一同定义，超出本公开契约的范围。
